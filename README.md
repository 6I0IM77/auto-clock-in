# Auto Clock-in · 自动打卡

上下班打卡助手（Android / Kotlin）。

一个只管两件事的 Android 小 App：**到点帮你打上飞书的上班卡和下班卡**，**打完立刻告诉你打上了**，然后把这一个月的出勤排成一张日历。

纯本地运行，不联网、不传数据，所有记录存在本机 SharedPreferences 里，卸载即失。

版本变化见 [CHANGELOG.md](CHANGELOG.md)。

> ⚠️ 只在本机、本人账号上模拟你自己的手动点击，不修改飞书数据、不伪造定位。是否允许自动打卡请先确认公司的考勤规定，使用风险自负。

## 功能

- **上下班两张卡**：上班、下班各自的打卡窗口都能自己设，默认 `09:00-10:00` / `18:00-19:00`
- **弹性顺延**：上班晚到几分钟，下班窗口的开始时间就顺延几分钟；下班窗口的**截止时间**按设置里的值走，不顺延
- **两种模式**：自动打卡（到点自己打开飞书点按钮）/ 仅提醒（只弹通知，由你点）
- **两条自动化通道**：无障碍服务（推荐，不用装别的）/ Shizuku（用 shell 权限读屏 + 点按）
- **成功反馈**：提示音 + 语音报时（「上班打卡成功，09:03」）+ 震动 + 屏幕中央卡片 + 通知栏
- **漏卡提醒**：截止时间后 5 分钟，这张卡还没打上就推一条，带「重试」「打开飞书」按钮
- **打卡提醒时间可调**：上班 = 窗口开始前 N 分钟；下班 = 窗口开启后 M 分钟
- **每种推送每天只发一次**：提醒 / 成功 / 漏卡都按「日期 + 类型」记账，不会反复轰炸
- **概览与日历**：双卡完成、只打一卡、缺卡三种状态；今天的结论要等下班窗口关门才下
- **保活**：前台常驻服务 + 15 分钟一次的自检闹钟 + JobScheduler + 开机自启 + 快捷设置磁贴（磁贴长按直接打开 App）
- **深色模式**：整套 `values-night` 配色跟随系统

## 编译

需要 JDK 17、Android SDK Platform 34、Build-Tools 34.x。

```bash
# Windows
gradlew.bat assembleDebug

# macOS / Linux
./gradlew assembleDebug
```

产物：`app/build/outputs/apk/debug/app-debug.apk`（debug 包名 `com.shuangka.punch.debug`，可与正式包共存）。

用 Android Studio 的话直接 `Open` 这个目录，同步后 `Run 'app'`。

## 装好之后按这几步开起来

进 App → 右上角「设置」：

1. **无障碍服务** → 开启（自动打卡的核心通道）
2. **悬浮窗** → 授权（屏幕中央那张成功提示卡要用）
3. **精确闹钟** → 授权（否则到点可能晚几分钟）
4. **通知权限** → 允许
5. **电池优化白名单** → 允许；小米 / 华为 / OPPO 还要额外给「自启动」「后台无限制」
6. （可选）装了 Shizuku 的话 → 点授权

设置里有「测试」分组：可以模拟 17 种场景（成功、失败、漏卡、节假日、调休、不在窗口内……）确认文案和样式，不会写真实记录。

## 打卡规则

App 不问「你要打上班还是下班」，而是看现在几点决定该打哪张卡：

| 时间段（工作日） | App 行为 |
| --- | --- |
| 上班窗口内 | 大按钮 = 上班打卡，可点；到点自动打开飞书去点 |
| 下班窗口内 | 大按钮 = 下班打卡，可点 |
| 其他时间 / 周末 | 大按钮变灰，按钮上直接显示「距上班打卡还有 28 分钟」这类倒计时 |

- **弹性**：今天上班打卡时间比窗口开始晚多少，下班窗口开始就顺延多少（最多不超过上班窗口长度）；截止时间不顺延，用设置里的值
- **判定成功**靠飞书页面文字：`应上班 09:22` / `已打卡 09:22` / `应下班 18:22` / `已打卡 18:22`；并用「现在是否在窗口内、页面时间是否在窗口内、页面时间与现在差多少」三道关防止把历史记录当成今天的
- **缺卡口径**：工作日无任何记录才算缺卡；今天的结论要等下班窗口关门后才下，窗口没关之前今天既不算缺卡也不算只打一卡

## 飞书页面不一样怎么办

App 靠文字找按钮，不同版本 / 不同公司的飞书打卡页文案可能不同。设置页可以改：进打卡页的点击路径（默认 `工作台>打卡`）、上班按钮文字、下班按钮文字、成功关键字（用 `|` 分隔多个候选）。

## 它到底做了什么

```
AlarmManager（打卡 / 提醒 / 漏卡 三套闹钟）
        │
        ▼
AlarmReceiver ── 自动模式且在窗口内 ──▶ PunchService（前台服务）
        │                                   │
        └── 否则 ──▶ 通知提醒                ├─ PunchFlow：打开飞书 → 沿路径点 → 点打卡按钮 → 校验
                                            │     ├─ 无障碍通道：AccessibilityNodeInfo 读屏 + ACTION_CLICK/手势
                                            │     └─ Shizuku 通道：uiautomator dump 读屏 + input tap
                                            ├─ 成功：写记录 + 音/语音/震动 + 中央浮层 + 通知
                                            └─ 失败：通知里可直接「重试」
```

旁路：无障碍服务一直盯着飞书窗口，你自己手动点完卡弹出「打卡成功」时，它也会识别、记账、播提示。

### 为什么这么设计

- **无障碍优先**：不用装额外软件、响应快、能拿到更多节点；缺点是会被系统回收，所以有保活自检和状态显示
- **还要 Shizuku**：有些系统或企业管控机型不给无障碍，Shizuku 用 shell 权限 `uiautomator dump` + `input tap` 一样能干
- **不上截图 OCR**：慢且不稳，文字节点足够判断
- **精确闹钟 + 前台服务 + 磁贴**：Android 12 起后台启动 Activity 受限，持有精确闹钟和悬浮窗权限属于豁免情形

## 已知限制

- 首次运行必须手动开一次无障碍 / 悬浮窗，没有「一键静默授权」这回事
- 飞书改版换了文案时需要去设置页改按钮文字，这是这套方案唯一的脆弱点
- 打卡依赖飞书处于登录态、网络正常；需要定位的考勤组还得人在范围内
- MIUI / HyperOS、EMUI、ColorOS 会压制后台，务必给「自启动」「后台无限制」
- 未做多账号、云同步、补卡申请联动
